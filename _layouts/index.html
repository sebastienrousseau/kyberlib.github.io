What it does

A post-quantum key exchange you can audit

Each card opens its section on the features page.

FIPS 203 ML-KEM

ML-KEM-512, ML-KEM-768 and ML-KEM-1024, the key-encapsulation mechanism NIST standardised from CRYSTALS-Kyber, behind one KemCore trait.

How the API is shaped

NIST ACVP conformance

All 180 key-generation, encapsulation and decapsulation vectors from NIST's ACVP server pass byte for byte, across the three parameter sets.

How conformance is tested

KyberSlash-clean arithmetic

No division or remainder on secret-derived values. A script in CI fails the build if one is reintroduced.

How timing leaks are kept out

No unsafe code by default

The default build compiles with unsafe code forbidden. Only the optional AVX2 backend opts back in.

How unsafe is contained

Secret keys that clean up after themselves

Decapsulation keys cannot be copied, are wiped from memory when dropped, and print as [REDACTED] in logs and panics.

How secrets are handled

WebAssembly and no_std

The core builds without the standard library for embedded targets, and kyberlib-wasm wraps it for browsers and JavaScript runtimes.

Where it runs

Parameter sets

Three security levels, one trait

All three implement KemCore and can be used together in one build. Sizes are in bytes.

NIST category 1

ML-KEM-512

Public key 800, secret key 1,632, ciphertext 768. The smallest keys and ciphertexts.

Compare the parameter sets

NIST category 3

ML-KEM-768

Public key 1,184, secret key 2,400, ciphertext 1,088. The default parameter set, and the one used by the hybrid TLS key exchange.

Compare the parameter sets

NIST category 5

ML-KEM-1024

Public key 1,568, secret key 3,168, ciphertext 1,568. The highest security level.

Compare the parameter sets

Install

A shared secret in ten lines of Rust

Add the crate, generate a key pair, encapsulate against the public key and decapsulate with the secret key. kyberlib needs Rust 1.74 or newer.

  • cargo add kyberlib
  • cargo add kyberlib-wasm

Security

Built to be checked, not taken on trust

kyberlib publishes its threat model, its constant-time claims function by function, and the checks behind them.

kyberlib has not had a third-party audit yet; version 1.0 will not be tagged until one is complete. The audit request for proposals and the materials package are in the repository.
